# 待办清单 · 使用说明

打开地址（管理员会发给你）：

```
http://你的服务器IP:30080/
```

**一～五节可以直接整段转发给用的人**，照着做五分钟就能用上。
**第六节是管理员（你自己）看的**：加人、备份、出问题怎么查。

---

## 一、随手记一条

1. 页面最上面那条 **「＋ 新建待办」**，点一下在页面里展开
2. 「要做的事」里写内容，比如 `处理磁盘告警 /data 写满`
3. 选 **优先级**：高 / 中 / 低（默认中）
4. 选 **分类**：工作 / 家里 / 学习
5. **截止日期选填**。不填就是"有空再说"，填了才会参与排序和微信提醒
6. 点 **「添加」**，或者直接按回车

按 `Esc` 或「取消」收起录入框。

> 只有填了截止日期的条目才会进微信提醒。没填的条目只是待在列表里，不会打扰你。

## 二、日常操作（都是点一下）

| 想做的事 | 怎么做 |
|---|---|
| 标记完成 | 点左边的圆圈 |
| 取消完成 | 再点一次圆圈 |
| 改文字 | **双击**那行文字，改完回车 |
| 改分类 | 点那行上的分类标签 |
| 改截止日期 | 点那行上的日期 |
| 删掉一条 | 点行尾的垃圾桶（没有二次确认，删错了只能重新加） |
| 按分类只看一类 | 点中间那排 **全部 / 工作 / 家里 / 学习** |
| 找某条 | 搜索框输关键词，边打边过滤，清空恢复全部 |
| 收起某一组 | 点分组标题（高 / 中 / 低） |
| 换个颜色 | 右上角那个小按钮，切深色 / 浅色 |

列表的固定规矩，不用记：

- **未完成在前**，已完成的沉到底部「已完成」那一组
- 组内 **高 → 中 → 低**，同优先级 **截止日期近的在前**
- 日期会显示成 **今天 / 明天 / 12月3日**；**逾期标红，今天到期标黄**

## 三、微信提醒（可选，但很值）

推送走的是 [Server酱](https://sct.ftqq.com)：**每个人用自己的 key，推到自己的微信，额度也各算各的，互不影响**，你不用管别人用了几条。

### 第 1 步：拿自己的 SendKey

1. 手机或电脑打开 **https://sct.ftqq.com**
2. 用 **微信扫码登录**
3. 复制那串 **`SCT` 开头**的字符（也可能以 `sctp` 开头）

> **最容易漏的一步**：登录后要用微信 **关注「方糖」服务号**。
> 不关注的话，消息发出去了你也收不到，而且**照样扣条数**。

### 第 2 步：填进页面

1. 页面拉到最下面，点 **「云同步」**
2. **服务器地址**：留空（网页就是这台服务器给的，留空即同源）
3. **SendKey**：粘刚才复制那串
4. **推送时间**：默认 `08:00`，想改就改成 `07:30` 这种格式
5. 点 **「立即上传」**，右下角变成 **「已同步」** 就成了

第二天早上到点，你会收到一条汇总，长这样：

```
待办：今天到期 2 件，逾期 1 件

已逾期 1 件
- 【高】交电费（11-14）

今天到期 2 件
- 【中】写周报
- 【低】买菜
```

几点说明：

- **一天只推一条**，到点后机器每 15 分钟看一次，所以可能比设定时间晚几分钟
- **只推「今天到期」和「已逾期」**，未来的不推。这两类一条都没有时 **故意不发**，省额度
- 免费版 **每天 5 条**，发失败也算。一个人一天一条，正常用不会超
- 想改待办内容后立刻生效，再点一次 **「立即上传」**就行（不用每天点，但改了重要内容建议点一下）

## 四、数据存在哪，丢了怎么办

**待办条目存在你自己的浏览器里**，不在服务器上。这意味着：

- 换浏览器、清浏览器数据、用无痕模式 → **数据不见了**
- 服务器挂了、断网 → **不影响你用**，只是那天不推微信

所以请养成两个习惯：

1. **每周点一次「导出 .sqlite」**，文件存到网盘或电脑上。真出事了点「导入 .sqlite」就能恢复
2. **记下「设备码」**（云同步面板里那串，「复制」按钮可以拷）

### 换电脑 / 换手机

数据不会自动跟着走，用设备码搬：

1. **旧设备**：打开「云同步」，点设备码右边的 **「复制」**
2. 把整串码发给自己（微信文件传输助手就行）
3. **新设备**：打开同一个网址 → 「云同步」→ 把码粘进「设备码」
4. 点 **「从云端拉回」**

> 设备码等于你的钥匙，别往群里发、别截图发出去。
> 「从云端拉回」会**覆盖本机全部待办**，点之前会弹框确认，建议先把本机那份导出一下。

## 五、收不到推送，按顺序查

1. **微信有没有关注「方糖」服务号** —— 九成的收不到都是这一条
2. 页面上点「立即上传」，看状态是不是 **「已同步」**
3. 今天是不是 **既没有逾期、也没有今天到期** 的待办 —— 这种情况设计上就不发
4. SendKey 是不是复制全了、有没有多余空格
5. Server酱 免费版 **每天 5 条**，用超了当天就不发了，第二天恢复

还不行，把下面这些告诉管理员，他能一眼看出问题在哪：
**你的推送时间**、**最后一次点「立即上传」大概是几点**、**微信里有没有收到过任何一条**。

## 六、不想收推送了

「云同步」里把 **SendKey 清空**，点「立即上传」。之后不再推给你，待办本身照常用。

# 管理员手册

## 发地址给同事

```
http://你的服务器IP:30080/
```

云厂商控制台的**安全组**要放行 **30080**。手机浏览器可以直接用，建议让同事「添加到主屏幕」。

## 加人 / 删人

- **加人不用做任何事**。他打开网页、点「立即上传」，服务器自动建目录，SendKey 也由他自己填的上传带过来
- **删人**（他离职、或者不想再留着数据）：

```bash
# 先看有哪些人（目录名是设备码的 sha256 前 16 位，不是设备码本身）
kubectl -n todo exec deploy/todo-app -c api -- ls -1 /data/users

# 删掉某一个
kubectl -n todo exec deploy/todo-app -c api -- rm -rf /data/users/<那串目录名>
```

## 每天看三眼

```bash
# 1) 服务活着没
kubectl -n todo get pod

# 2) 今天推了没、谁失败了
kubectl -n todo exec deploy/todo-app -c api -- tail -n 30 /data/push.log

# 3) 某个人为什么没收到（他的最后一次请求和 Server酱 的原始回复）
kubectl -n todo exec deploy/todo-app -c api -- cat /data/users/<目录名>/last.log
```

推送日志只看开头几个词就够：

| 开头 | 意思 |
|---|---|
| `OK` | 发出去了 |
| `SKIP` | 没发。后面会写原因：没填 SendKey / 没上传过 / 今天既没逾期也没到期 |
| `FAIL` | 发了但失败。后面有 curl 返回码和 Server酱 的错误码 |
| `GIVEUP` | 今天失败次数到上限，今天不再试，**明天自动重来** |
| `DRY` | 只是预览，没发 |

## 备份

```bash
cd /root/todo-push/k8s && ./backup.sh
```

所有用户的数据、每个人的配置、网页本体，一次打包。建议配个 cron 每天跑一次，扔到别的机器上。

## 想手动给某个人推一条

```bash
# 先只看判定，不发（零额度消耗）——排查"为什么他没收到"先跑这个
kubectl -n todo exec deploy/todo-app -c api -- env SCAN_ONLY=1 /opt/todo-push/push-all.sh

# 只预览正文，不发送
kubectl -n todo exec deploy/todo-app -c api -- env DRY=1 /opt/todo-push/push-one.sh /data/users/<目录名>
```

## 常见故障对照

| 现象 | 先看这里 |
|---|---|
| 网页打不开 | `kubectl -n todo get pod`；安全组 30080 |
| 网页能开，但点上传报错 | `kubectl -n todo logs deploy/todo-app -c api --tail=50` |
| 所有人都不推 | `push.log` 有没有 `TICK`；`kubectl -n todo get cronjob todo-push` 是不是被人 `suspend` 了 |
| 某个人不推 | 他的 `last.log`；多半是没关注「方糖」或者 SendKey 填错 |
| 改了 nginx 配置没生效 | 改完必须 `kubectl -n todo rollout restart deploy/todo-app` |
| 磁盘满了 | `df -h /var/lib/rancher`，PVC 是 2Gi，超了先备份再扩 |

## 别忘了

- **删 PVC = 删所有用户数据**，动之前先 `./backup.sh`
- 数据目录在节点的 `/var/lib/rancher/k3s/storage/*_todo_todo-data/`，需要直连磁盘就从这个路径拿
- 完整自检：`cd k8s && ./check.sh`，会一项项告诉你哪儿不对
